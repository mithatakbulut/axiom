# Flight Recorder hook contract

`vigil hook [--config path]` reads at most 256 KiB as one JSON object. It accepts the lifecycle events in the plan, plus PermissionRequest and Interrupt, and requires a session ID. The receipt time is UTC; it is not a timestamp supplied by Codex. A passive hook normally emits no output and exits zero. Stop can emit a diagnostic `systemMessage` or an opt-in continuation decision. A rejected input or storage failure emits a generic JSON error to stderr and a generic `systemMessage` on stdout, then exits zero. Codex surfaces informational output only on supported hook paths; failures on diagnostic or advisory hooks may not appear in the UI.

Progress tracks concurrent permission requests by tool-use ID. A matching post-tool event clears that request; an unrelated completion does not. If a permission request has no ID, its resolution cannot be correlated, so escalation stays suppressed until the next user prompt. This conservative fallback may suppress a candidate after an approval has actually resolved.

Only selected identifiers, tool name, agent type, documented enumerations, booleans, bounded numeric values and supported token counters are stored. Working directory, prompts, tool inputs, tool output, error messages, transcript paths and hidden reasoning are not stored. Pattern filtering is defense in depth, not a guarantee for arbitrary identifiers: trusted hook producers must not put secrets in ID or name fields. Existing databases created by older versions can contain previously stored metadata; this change does not retroactively scrub them.

For structured tool results, numeric `exit_code` and boolean `isError` are observed. For Bash and recognized shell tool text results, Vigil extracts the exit envelope, explicit test counts, a few transient network signatures and hashes selected normalized failure lines. No original output is stored. Unrecognized failures receive coarse fingerprints. A model event may supply numeric `token_usage` fields; absent or unrecognized usage remains unknown. Tool duration is computed in summaries only when both endpoints share a session, turn and tool-use ID and are ordered. Hook timing includes hook delivery overhead. No model-request duration is invented without a reliable correlation ID. Advisor runs have a separate durable reservation and outcome.

Codex does not document a universal unique event ID. The recorder hashes the entire input and suppresses byte-identical payloads. This protects identical retries but can also collapse independent identical events, and equivalent JSON with different encoding will not deduplicate. Hashes may reveal equality and are not encryption. Retention deletes old events during a subsequent insert. Session summaries cover retained and observed events only; missing hooks, unknown statuses, and missing usage are not zero-valued facts.

The hook event list is based on [official OpenAI documentation](https://developers.openai.com/codex/hooks); support varies by installed version and surface, and specialized and hosted tools may not emit tool hooks. SessionEnd is synchronous; asynchronous hooks may finish out of order or be cancelled. See the [installation workflow](../README.md#install-and-remove-codex-integration) for the baseline event set and Codex trust review.

Progress suppresses candidates while any observed, identifiable tool use is in flight, even if it has no command fingerprint. A matching post-tool event clears it. Missing IDs or missing/out-of-order hooks cannot be reliably correlated, and a missing completion can conservatively suppress a candidate. The existing `commands_in_flight` signal also covers non-command tools.

A tool response supplies test counts only when it contains exactly one recognized `Tests: N passed, M failed` line. Multiple recognized summaries are ambiguous and yield no counts, preventing linked test evidence from being treated as verified from the first summary alone. Unrecognized formats and output outside the captured response remain limitations. Previously stored counts cannot be corrected retrospectively because raw output is not retained.
